# 2.6 — Verification Protocol, Review Checklist & Open Questions

**Status:** Working draft — owner approval pending

## Source hierarchy
1. **Current direct evidence** — a working product demonstration, current release record, or authoritative product documentation. State precisely what the evidence proves.
2. **Current canonical public source** — evidence of what the public page currently says; not by itself proof of implementation.
3. **Dated internal records** — useful for the product vision and owner decisions, but implementation claims require separate support.
4. **Prior conversations, assumptions, mock-ups, and plans** — useful context only; not proof that a feature exists or that demand is validated.
5. **Unsupported claims** — omit or mark unknown.

The repository's source register currently names S1 as the public website, S2 as owner-provided context, and S3 as prior project conversation history. Source precedence says S1 governs current public status while S2 explains broader internal vision.

## Verification record for every material claim

| Field | Required entry |
|---|---|
| Claim | Exact wording the team wants to use |
| Evidence status | Publicly stated / Internal record / Hypothesis / Unknown / Conflicting |
| Source | URL, repository path, or evidence artifact |
| Date checked | Exact date, not “recently” |
| What it supports | Narrow, factual statement |
| What it does not support | Relevant limits and inferences that cannot be made |
| Owner / reviewer | Person or role responsible for confirmation |
| Public use | Allowed / Allowed with caveat / Hold / Prohibited |
| Recheck date | Required for changeable status claims |

## Release gate before an agent uses product claims
- [ ] Is the current canonical public page accessible and checked?
- [ ] Is the source date visible?
- [ ] Does the evidence prove the exact wording—not merely a nearby or broader idea?
- [ ] Is the claim about a concept clearly separated from a live feature?
- [ ] Are mock-ups labelled as illustrative when relevant?
- [ ] Are internal technologies described as “explored” unless integration is evidenced?
- [ ] Are health, clinical, safety, privacy, and security claims supported and approved?
- [ ] Are all unknowns and conflicting sources retained rather than silently resolved?
- [ ] Has the owner approved the product-status statement and the capability matrix?

## Open questions requiring owner evidence

### Current status
1. Is https://getrenomedy.framer.website/ still the canonical public website?
2. Does the page still say “in development / not yet available”?
3. What is the actual current development/release status, and what dated evidence confirms it?
4. Is there a working waitlist, demo, or other CTA? If yes, what exact destination has been tested?

### Capability matrix
5. For each capability in [2.3](2.3.md), what is the current status: Live, Prototype, Planned, Dropped, or Unknown?
6. What evidence proves each item labelled Live or Prototype?
7. Which capabilities are explicitly out of scope or dropped?

### AI and safety
8. Which AI/OCR components, if any, are actually integrated in a working build?
9. What evaluation evidence exists for prescription-related inputs, and what are its limits?
10. What human-confirmation and uncertainty-handling safeguards exist today?

### Privacy and trust
11. Which privacy and security controls are implemented, and where is the authoritative evidence?
12. What retention, deletion, permissions, and data-access rules actually apply?
13. Is there any clinical, regulatory, or independent security review? What precisely was reviewed?

### Customer evidence
14. Which audience and problem hypotheses have been tested with real users?
15. What evidence supports the strongest pain points, and what remains opinion or inference?
16. Which segment and geography are priorities, and what data supports those choices?

## Final rule
When uncertain, state what is known, cite where it came from, state the limitation, and leave the unresolved question open. Never fill a gap with a plausible-sounding claim.
