# 5.3 — Visual QA and Design-Token Governance

**Status:** Working draft — owner approval pending

## Before approving a visual change
1. Identify the source of truth: deployed page, approved design file, or owner-confirmed asset.
2. Compare the proposed change with the actual current experience.
3. Record exact token/file changes and why they are needed.
4. Check desktop and mobile layouts, text wrapping, focus states, and status disclaimers.
5. Run contrast and accessibility checks on the affected combinations.
6. Confirm that concept screens remain labelled as illustrative.
7. Obtain owner approval and update the token register.

## No unsupported claims
Do not state that a design system is complete, WCAG-compliant, production-matched, or formally approved unless there is an actual review record supporting that exact statement.

## Current evidence gaps
- Canonical design source and exact token files.
- Final brand colors and typography.
- Responsive breakpoints and spacing scale.
- Accessibility audit scope and results.
- Asset ownership/licensing records.

## Exit checklist
- [ ] Tokens are extracted from current files, not guessed.
- [ ] Each token is labelled observed, proposed, approved, or superseded.
- [ ] Accessibility results are documented.
- [ ] Owner signs off on the visual rules.
