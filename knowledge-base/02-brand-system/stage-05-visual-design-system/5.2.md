# 5.2 — Typography, Layout and Accessibility Rules

**Status:** Preference-aware working draft — owner approval pending

## Typography evidence status
Prior project context records a preference to keep the existing landing-page heading and body fonts. It also records DM Serif Display Regular for headings, DM Sans Regular for body text, and DM Sans Semibold for labels. The fact ledger says final typography is not established by the reviewed source. Treat those names as candidates until inspected in the current site assets/styles and approved; do not replace existing typography based on memory alone.

## Typography register
Record family, weight, source file, license/source, usage role, fallback stack, actual deployed usage, and owner approval. Check that loaded font files match the stated family and weight. Do not claim a font is loaded just because a CSS declaration names it.

## Layout and readability principles
- Keep heading/body hierarchy consistent and understandable.
- Avoid using small text to carry essential product-status, safety, or privacy qualifications.
- Keep illustrative screens visibly labelled when there is a risk of mistaking them for live UI.
- Ensure responsive layouts do not hide caveats or important actions.
- Use semantic hierarchy and readable line lengths; validate in actual rendered contexts.

## Accessibility verification
Contrast, keyboard focus, screen-reader structure, zoom/reflow, target size, and motion behavior must be tested on the actual experience. No compliance claim is permitted until evidence documents the applicable standard, tested scope, date, and results.
