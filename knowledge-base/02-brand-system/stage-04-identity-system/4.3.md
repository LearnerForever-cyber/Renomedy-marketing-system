# 4.3 — Identity Decisions and Verification Checklist

**Status:** Working draft — owner approval pending

## Decision record
Every identity decision that future agents must obey should include the exact decision, status (proposed/owner-approved/superseded), approving person, date, asset or evidence link, scope, and review trigger. Do not infer approval from repeated use or an AI-generated draft.

## Current known / unknown split
**Recorded public wording:** Renomedy; “Care works better, together.” (source register S1 snapshot).

**Not verified in reviewed evidence:** legal trademark status; exact approved logo/mascot file; canonical mascot name; final color and type tokens; language-specific lockups; clear-space rules; formal accessibility checks.

## Before producing new brand assets
1. Search the existing repository and project files for the current approved source asset.
2. Confirm with the owner if multiple versions conflict.
3. Use the approved source asset rather than recreating it from a screenshot where possible.
4. Label exploratory concepts as proposals.
5. Store the approved file and update the asset register.

## Exit checklist
- [ ] Canonical assets and brand lines are linked.
- [ ] All identity rules have explicit status and provenance.
- [ ] Unapproved details are not presented as final.
- [ ] Legal and accessibility claims are not inferred from design approval.
